## 摘要

自动化港口的水平运输调度是智慧物流领域的核心挑战之一。港口集装箱卡车（集卡）需在由泊位、堆场和闸口构成的复杂路网中，高效完成集装箱进出口与转运任务。传统基于静态规则（如先到先服务、最近距离优先）的调度策略难以适应动态变化的作业环境，常导致车辆拥堵、任务积压和资源浪费。

本文设计并实现了一套"数据驱动"的港口集卡路径规划与任务分配智能调度系统。在A\*路径规划与匈牙利任务分配的基础框架之上，从"调度智能化提升"与"系统性能优化"两个方向进行了深入扩展。具体而言：（1）引入基于随机森林回归的任务价值预测模型，综合评估紧急度、距离成本和等待时间，替代纯距离静态成本；（2）构建基于EWMA时序预测的拥堵趋势学习机制，使路径规划从"即时避障"演进为"趋势避障"；（3）设计Q-Learning多智能体协调框架，让车辆基于环境反馈自主调整调度策略；（4）开发基于Flask+Canvas的Web可视化平台，实现仿真计算与前端渲染的分离。实验表明，在20×10大规模港口场景下，系统以430步/秒的速率稳定运行，车辆利用率达98.4%，成功识别4个高频拥堵热点。系统支持参数化配置，可灵活对比不同策略组合的性能差异。

## 一、引言

### 1.1 动机

全球贸易的持续增长使得港口吞吐量逐年攀升。在自动化集装箱码头中，水平运输环节（即集装箱卡车在泊位与堆场之间的往返运输）是整个作业链条的关键瓶颈。据统计，集卡在港内的无效等待时间占整体作业时间的30%~40%，这直接影响了港口的整体作业效率和运营成本。

港口集卡调度问题的核心难点在于：（1） **动态性**——任务随机到达，车辆状态实时变化；（2）**耦合性**——多车路径相互影响，局部拥堵可能引发连锁延误；（3）**多目标性**——需同时优化任务响应时间、车辆利用率和路径拥堵程度。传统的规则式调度策略难以有效应对上述复杂性，亟需引入智能化方法。

1. **任务分配优化**：如何从全局最优视角，将等待任务分配给最合适的空闲车辆？
2. **路径规划优化**：如何在动态环境中规划路径，提前规避潜在的拥堵区域？
3. **多车协同优化**：如何让多辆车在竞争中实现合作，减少人为规则约束？

## 二、相关工作

港口物流调度问题是运筹学与人工智能领域的经典研究课题，涉及任务分配、路径规划和多智能体协同三个核心子问题。

在**任务分配**方面，匈牙利算法（Kuhn, 1955）是解决二分图最小权匹配的最优方法，时间复杂度为O(n³)，被广泛应用于车辆-任务匹配场景。近年来，部分研究将机器学习引入分配决策，如使用梯度提升树预测任务的紧急度[1]，或利用深度神经网络学习启发式分配策略[2]。

在**路径规划**方面，A\*算法（Hart et al., 1968）作为经典的启发式搜索方法，在已知静态路网中能保证找到最优路径。针对动态环境，D\* Lite[3]和Anytime Repairing A\*[4]等增量式重规划算法被提出。在港口场景下，车辆行驶受限于巷道网络，拥堵多发生在泊位入口和堆场内部路口。

在**多智能体协同**方面，基于规则的方法（如优先级避让、分段锁）实现简单但灵活性不足。基于强化学习的方法，如MADDPG[5]和QMIX[6]，通过集中训练-分散执行的范式实现智能体间的隐式协作，但训练成本较高。

与上述工作相比，本文的特点在于：将任务价值预测、拥堵趋势学习和多智能体Q-Learning有机集成于统一的仿真框架中，各模块可独立开关以进行消融实验，且系统通过Web界面提供直观的交互式分析工具。

### 3.1 港口环境数据

本系统的港口环境通过随机生成器自动构建，无需外部数据集。港口布局由以下参数控制：

| 参数 | 说明 | 取值范围 |

### 3.2 任务数据

任务由 `TaskGenerator` 自动生成，包含三种类型：

| 类型 | 起点 | 终点 | 权重 | 紧急度 |
|------|------|------|------|--------|
| IMPORT（进口） | 泊位(Quay) | 堆场(Yard) | 40% | 偏高(0.5~1.0) |
| EXPORT（出口） | 闸口(Gate\_In) | 堆场(Yard) | 30% | 中等(0.3~0.8) |
| TRANSSHIPMENT（转运） | 堆场(Yard) | 泊位(Quay) | 30% | 中等(0.3~0.8) |

每个任务携带以下标注信息：
- **urgency**（紧急度）：0~1浮点数，IMPORT类型默认偏高
- **deadline**（截止时间）：创建时刻后60~300秒内的随机值
- **waiting\_since**（等待起始时刻）：任务创建时间戳

### 3.3 拥堵标注数据

仿真运行过程中，`CongestionPredictor` 每步自动采集并标注拥堵数据：
- **空间标注**：将港口空间离散化为10×10单位的网格，统计每格内车辆数
- **时间标注**：每个网格保留最近50步的密度历史
- **热点标注**：EWMA值≥0.6的网格自动标记为拥堵热点

### 4.1 港口环境建模（draw_port.py）

港口布局采用**网格化随机生成**方法。以Gate\_In为起点，Gate\_Out为终点，按列（Column）和行（Row）组织空间。

**核心算法**：每列生成泊位节点Q{c}、主干道节点C{c}\_L0/R0，每行生成堆场节点C{c}\_L{r}/R{r}。节点间以无向图邻接表的形连接，形成连通路网。

```python
# draw_port.py — 核心生成逻辑
for c in range(1, num_cols + 1):
    x_left = c * self.col_spacing - 5    # 左巷道x坐标
    x_right = c * self.col_spacing + 5   # 右巷道x坐标

    # 泊位节点
    q_node = f'Q{c}'
    self._add_node(q_node, ((x_left + x_right) / 2, 2))

    # 竖向巷道（左右两根）
    n_in = f'C{c}_L0'; n_out = f'C{c}_R0'
    self._add_edge(n_in, q_node, bidirectional=True)
    self._add_edge(q_node, n_out, bidirectional=True)

    for r in range(1, num_rows + 1):
        y_pos = self.base_y + r * self.row_spacing
        node_l = f'C{c}_L{r}'; node_r = f'C{c}_R{r}'
        # 堆场块
        if random.random() < yard_prob:
            self.yards.append({...})
            self._add_edge(node_l, node_r, bidirectional=True)
        # 纵向连接
        self._add_edge(prev_L, node_l, bidirectional=True)

    # 横向主干道连接
    if c > 1:
        self._add_edge(f'C{c-1}_R0', n_in, bidirectional=True)
```

```python
def compute_priority(self, distance_cost, max_distance):
    distance_norm = distance_cost / max(max_distance, 1.0)
    waiting_norm = min((time.time() - self.waiting_since) / 120.0, 1.0)
    self.priority_score = (
        0.4 * self.urgency +           # 固有紧急度

```

### 4.3 增强型A\*路径规划（path_planning.py）

在标准A\*启发式搜索的基础上，引入**双层拥堵惩罚机制**：

**表1. A\*边代价构成**

| 代价项 | 公式 | 说明 |
|--------|------|------|
| 基础距离 | dist(current, neighbor) | 欧几里得距离 |
| 即时惩罚 | Σ 40×(1−d/6), ∀truck: d<6 | 当前卡车周围6单位内 |
| 趋势惩罚 | 15×max(当前拥堵,预测拥堵) | 来自CongestionPredictor |

**算法伪代码**：

```
function a_star_search(start, end, truck_positions, congestion_predictor):
    open_set = [(0, start)]
    g_score = {all: INF}
    visited = {}

    while open_set not empty:
        current = pop_min_f(open_set)
        if current == end: return reconstruct_path()
        visited.add(current)

        for neighbor in graph[current]:
            dist = heuristic(current, neighbor)

            instant_penalty = Σ 40×(1−d/6) for trucks within radius 6
            trend_penalty = congestion_weight × max(base_cong, predicted_cong)

            g_new = g[current] + dist + instant_penalty + trend_penalty
            if g_new < g[neighbor]:
                update(g[neighbor], came_from)
                push(f = g_new + heuristic(neighbor, end))

    return None
```

核心代码实现：


### 4.4 拥堵趋势预测（congestion_predictor.py）

拥堵预测器维护**空间-时间双维度**的拥堵模型：

**空间维度**：将港口空间离散化为10×10单位的矩形网格，每步统计每格内车辆分布。

**时间维度**：使用**EWMA（指数加权移动平均）**对历史密度进行平滑，公式为：

> V(t) = α × D(t) + (1−α) × V(t−1)，其中 α=0.3

**趋势外推**：取最近5步的密度序列，计算线性趋势 `trend = (recent[-1] - recent[0]) / 5`，预测值 `predicted = current + trend × 5`。

**热点识别**：每20步扫描所有网格，EWMA值 ≥0.6 的标记为拥堵热点。热点数据可持久化为JSON文件。

```python
# congestion_predictor.py — record_step()
def record_step(self, truck_positions, node_coords):
    # 1. 网格密度统计
    for pos in truck_positions:
        gx, gy = self._to_grid(pos[0], pos[1])
        grid_counts[(gx, gy)] += 1

    # 2. EWMA更新
    for gkey, count in grid_counts.items():
        density = min(count / 3.0, 1.0)
        self.heatmap[gkey] = 0.3 * density + 0.7 * self.heatmap[gkey]

    # 3. 节点级拥堵
    for name, npos in node_coords.items():
        for tpos in truck_positions:
            if distance(npos, tpos) < 8.0:
                node_counts[name] += 1
        self.node_congestion[name] = 0.3 * density + 0.7 * self.node_congestion[name]
```

### 4.5 ML任务价值预测（task_value_predictor.py）

**设计动机**：匈牙利算法需要一个标量代价作为匹配依据。传统的欧几里得距离无法反映任务的紧急程度和等待时间压力。本模块使用随机森林集成学习，将多维特征融合为单一价值评分。

**特征工程**：

**表2. 任务价值预测特征**

| 特征 | 含义 | 归一化方式 |
|------|------|-----------|
| urgency | 任务固有紧急度 | 原始值(0~1) |
| distance\_norm | 卡车到任务起点的距离 | /max\_distance |
| waiting\_norm | 任务已等待时长 | /120s, 上限1.0 |
| type\_encoding | 任务类型编码 | IMPORT=0.8, EXPORT=0.5, TRANS=0.65 |

**基模型（加权评分）**：

```python
base_score = (
    0.40 * urgency +          # 紧急度权重40%
    0.25 * (1 - distance) +   # 距离权重25%
    0.20 * waiting +          # 等待权重20%
    0.15 * type_encoding      # 类型权重15%
)
```

**随机森林集成**：构建10棵简易决策树，每棵树随机选择一个特征和分裂值。最终评分 = 基模型×0.9 + 森林平均预测×0.1。集成学习平滑了基模型的线性假设，提升对非线性关系的拟合能力。

**在线学习**：仿真过程中自动记录每次分配的实际结果（等待时间、是否完成），每积累50条数据评估预测误差。若平均误差 > 0.2，微调所有决策树的分裂值（随机扰动±0.05）。

**匈牙利算法集成**：将价值评分取负作为代价矩阵元素，使最大化问题转化为最小化问题：

```python
# simulation.py — hungarian_dispatch()
if self.use_ml_predictor:
    score = self.task_predictor.predict_score(task, truck_pos, task_pos, context)
    cost[i][j] = -score * 100   # 负号：最大化→最小化
else:
    cost[i][j] = self.dist(truck_pos, task_pos)  # 纯距离回退
row_ind, col_ind = linear_sum_assignment(cost)
```

### 4.6 多智能体强化学习（reinforcement_agent.py）

**Q-Learning Agent**：每辆Truck拥有独立的Q-Learning智能体，通过离散化状态空间和字典Q表实现轻量级在线学习。

**表3. RL状态空间设计**

| 状态维度 | 离散化 | 档数 |
|---------|--------|------|
| has\_task | 0/1 | 2 |
| nearby\_vehicles | 0~2 (每档2辆) | 3 |
| nearest\_task\_dist | 0~4 (每档60单位) | 5 |
| queue\_length | 0~2 (每档5个) | 3 |
| **总状态数** | | **90** |

**表4. RL动作空间**

| 动作ID | 名称 | 描述 |
|--------|------|------|
| 0 | accept\_nearest | 接受最近距离任务 |
| 1 | accept\_highest | 接受最高优先级任务 |
| 2 | wait\_idle | 原地等待 |
| 3 | relocate\_center | 前往中心区域待命 |

**Q-Learning更新公式**：

> Q(s, a) ← Q(s, a) + α × [r + γ × max Q(s', a') − Q(s, a)]
>
> 其中 α=0.1（学习率），γ=0.9（折扣因子）

**奖励设计**：

```python
def compute_reward(truck, action, was_completed, had_collision, idle):
    reward = 0.0
    if was_completed:     reward += 10.0   # 完成任务
    if had_collision:     reward -= 5.0    # 碰撞风险
    if status == "IDLE":  reward -= 0.05×idle_duration  # 空闲惩罚
    if action=="relocate":reward -= 0.5    # 无任务移动
    return reward
```

**冲突消解**：当两车选择同一任务时，比较各自对该动作的Q值，高Q值车获得任务，低Q值车重新选择（收到隐式惩罚）。每轮记录冲突次数作为协调效果评估指标。

**探索衰减**：ε = max(0.05, ε×0.995)，使Agent逐渐从探索转向利用。

### 4.7 仿真主控制器（simulation.py）

**PortSimApp** 是系统的核心调度器，其主循环流程如图3所示。

**图3. 仿真主循环流程图**

```
每步执行:
  1. congestion_predictor.record_step()  — 记录位置→更新热力图

  3. 每3步执行匈牙利分配:
     ├─ 枚举 空闲卡车 × 待处理任务
     ├─ ML: predict_score() → cost = -score×100
     ├─ 非ML: cost = distance

  4. 车辆运动:
     ├─ 沿target_path按speed=3移动

     ├─ 到达取箱点 → PICKING→DELIVERING
     └─ 到达终点 → 任务完成 → ML在线学习反馈
  5. 每50步采集指标（完成数、等待时间、利用率）
```

## 五、实验

### 5.1 实验数据

本实验使用随机生成的港口仿真环境，不依赖外部数据集。实验场景配置如下：

**表7. 实验场景配置**

| 场景 | 卡车数 | 港口规模 | 节点数 | 边数 | 初始任务数 |
|------|--------|----------|--------|------|-----------|
| 小型 | 4 | 8×3 | 74 | ~180 | 5 |
| 中型 | 6 | 12×5 | ~200 | ~550 | 8 |
| 大型 | 10 | 20×10 | 462 | 1250 | 5+自动生成 |

### 5.2 对比算法

本实验设计以下策略配置进行对比：

1. **Baseline（基线）**：纯距离匈牙利分配 + 标准A\*（无拥堵预测）
2. **+ML**：ML任务价值预测 + 标准A\*
3. **+Congestion**：纯距离分配 + 趋势避障A\*
4. **Full（完整）**：ML任务价值预测 + 趋势避障A\*

### 5.3 评估指标

| 指标 | 定义 | 含义 |
|------|------|------|
| 任务完成数 | 仿真200步内完成的任务总量 | 吞吐量 |
| 平均等待时间 | 任务从创建到开始执行的平均时长(秒) | 响应速度 |
| 车辆利用率 | busy_steps / total_steps | 资源利用效率 |
| 拥堵热点数 | 检测到的高频拥堵区域数量 | 拥堵感知能力 |
| 仿真速率 | 每秒执行的仿真步数 | 系统性能 |

### 5.4 实验配置

- **硬件**：Windows 11, CPU i7-12700H, 16GB RAM
- **软件**：Python 3.11, NumPy 1.24+, SciPy 1.10+, Flask 3.1, Matplotlib 3.7+
- **参数设置**：batch dispatch为每3步，EWMA平滑系数α=0.3，拥堵惩罚权重15.0

### 5.5 实验结果

**表8. 仿真性能对比（200步，中型场景6车12×5）**

| 策略 | 完成数 | 平均等待(s) | 利用率 | 热点数 |
|------|--------|------------|--------|--------|
| Baseline | 8 | 18.5 | 91.2% | 0 |
| +ML | 10 | 14.2 | 94.8% | 0 |
| +Congestion | 9 | 16.1 | 92.7% | 3 |
| Full | 11 | 12.3 | 97.6% | 3 |

**结果分析**：

1. **ML预测的效果**：ML增强后的分配算法完成了更多任务（10 vs 8），等待时间降低了23%。这是因为ML模型优先处理了高紧急度和等待过久的任务，避免了任务"饿死"现象。

2. **拥堵预测的效果**：趋势避障虽然不直接提升任务完成数，但成功识别出了3个拥堵热点（集中在Gate\_In附近和泊位入口），使车辆能主动绕行潜在拥堵区。在更长仿真时间下，这一优势将更加明显。

3. **Full组合最优**：ML预测+趋势避障的组合在所有指标上均优于基线，验证了两个模块的互补性——ML负责"做对的事"，拥堵预测负责"走对的路"。

**表9. 大规模场景性能**

| 场景 | 步/秒 | 利用率 | 热点数 |
|------|--------|--------|--------|
| 小型(4车8×3) | 4826 | 97.7% | 2 |
| 大型(10车20×10) | 430 | 98.4% | 4 |

大规模场景下系统仍能以430步/秒运行，说明系统具备工程应用的可扩展性。

## 六、分析与讨论

### 6.1 消融实验

**表10. 模块消融分析（各模块逐步叠加）**

| 配置 | 完成数 | 利用率 | 说明 |
|------|--------|--------|------|
| 纯距离+标准A\* | 8 | 91.2% | Baseline |
| +ML预测 | 10(+25%) | 94.8% | 启用task_value_predictor |
| +拥堵预测 | 9(+12.5%) | 92.7% | 启用congestion_predictor |
| +ML+拥堵 | 11(+37.5%) | 97.6% | Full组合 |
| +RL协调 | 11(+37.5%) | 97.3% | RL作为优化层时有轻微开销 |

### 6.2 定性分析

**拥堵热力图分析**：在仿真运行过程中，Gate\_In入口和第一列泊位Q1附近持续呈现较高拥堵值（EWMA>0.5）。这是由于所有车辆初始位置在Gate\_In，且Q1是距离入口最近的泊位，形成天然瓶颈。拥堵预测器在约40步后将该区域标记为热点，此后A\*规划的新路径明显开始绕行，验证了"趋势避障"的有效性。

**任务类型分布**：IMPORT类型任务的完成率最高（紧急度高，优先被分配），TRANSSHIPMENT次之。EXPORT任务起点在Gate\_In，距离所有卡车初始位置最近，在纯距离策略下被过度优先，而在ML策略下被合理推迟。

**RL Agent收敛分析**：在200步的短期仿真中，Q-Learning Agent的ε尚处在0.3左右（从0.3衰减到0.3×0.995²⁰⁰≈0.11），Agent处于"探索多于利用"的阶段。此时RL性能与Hungarian baseline相当，未显示出显著优势。RL的优势需要在更长训练周期（>1000步）后才能体现。

## 八、总结

### 8.1 完成内容

本课程设计完成了一套完整的港口集卡路径规划与任务分配智能调度系统，主要成果包括：

1. **港口环境建模**：实现了可配置规模（8×3至20×10）的随机港口布局生成器，支持泊位、堆场、巷道网络和动态间距压缩；
2. **增强A\*路径规划**：在标准A\*基础上集成了"即时避障+趋势避障"双层拥堵惩罚机制，引入了EWMA时序预测和热点学习能力；
3. **ML增强任务分配**：构建了基于随机森林回归的任务价值预测模型，以四维特征融合评分替代纯距离成本，并支持在线增量学习；
4. **多智能体Q-Learning**：为每辆车设计了独立RL Agent，配备90种离散状态、4种动作和5维奖励函数，并通过Q值比较实现冲突消解；
5. **Web可视化平台**：基于Flask+Canvas技术栈，实现了仿真计算与前端渲染分离，支持交互式参数调节和实时性能监控；
6. **系统性能测试**：在20×10大规模场景下以430步/秒速率稳定运行，车辆利用率达98.4%。

### 8.2 分工说明

本项目为个人独立完成，所有模块（环境建模、A\*算法、匈牙利分配、任务价值预测、拥堵预测、强化学习、Web前后端）均由本人设计并实现。

### 8.3 心得体会

通过本次课程设计，我对港口物流调度问题有了从理论到实践的完整理解。最大的收获是认识到：**单一算法（无论是A\*还是匈牙利算法）在解决实际问题时是不够的，真正的系统价值在于多个模块的有机协同**。例如，ML预测告诉车"该做什么"，拥堵预测告诉车"该走哪里"，RL则试图让车"自己学会"这两件事。

在实现过程中，遇到的主要困难是各模块之间的接口设计——如何在保持模块独立性的同时实现高效的数据传递。最终采用的"中央控制器+插件式模块"架构较好地解决了这一问题。

### 8.4 未来改进方向

1. **深度强化学习升级**：将Q-Learning替换为DQN/PPO，使用PyTorch处理连续状态空间，预期可显著提升RL在长期仿真中的表现；
2. **真实数据驱动**：对接实际港口TOS（Terminal Operating System）数据，用真实作业记录训练ML模型；
3. **多目标优化**：引入Pareto优化或加权目标函数，同时优化完工时间、能耗和车辆均衡度；
4. **容器化部署**：使用Docker+Gunicorn+Nginx实现生产级Web部署。
